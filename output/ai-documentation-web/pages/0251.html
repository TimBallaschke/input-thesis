442## Verarbeitung und ihre Maßstäbe
443
444### Wann beginnt Verarbeitung?
445
446Eine Eingabe wird nicht notwendig erst mit dem Ab-
447senden verarbeitet. Bereits die Veränderung eines
448Eingabefeldes kann technische Vorgänge auslösen, ohne
449dass der eingegebene Text schon übermittelt oder
450eine damit verbundene Operation ausgeführt wurde. Bei
451HTML-Eingabefeldern wird etwa zwischen der Verän-
452derung eines Wertes und der späteren Übermittlung eines
453Formulars unterschieden (vgl. WHATWG 2026, Abschn.
4544.10.5.5 und 4.10.22.3). [cite: turn944464search1:
455turn944464search2]
456
457Besonders deutlich wird diese Unterscheidung bei Such-
458feldern. Chromium kann bereits während der Eingabe
459neue Suchvorschläge abrufen. Für eine als wahrschein-
460lich angenommene Vervollständigung kann außerdem eine
461Ergebnisseite vorab geladen werden, bevor NutzerInnen
462diese Anfrage tatsächlich auswählen und aufrufen.
463Ein technischer Abruf kann somit bereits stattfinden,
464während die endgültige Suchanfrage noch nicht fest-
465steht (vgl. The Chromium Projects 2026, *Omnibox Pre-
466fetch and Prerender for Default Search Engines*).
467[cite: turn862561search0]
468
469Feldänderung, Übermittlung und Ausführung sind deshalb
470als unterschiedliche Vorgänge zu betrachten. Das Ab-
471senden markiert einen möglichen Übergang innerhalb der
472Verarbeitung, nicht aber deren grundsätzlichen Beginn.
473
474### Wie wird verarbeitet?
475
476Was nach einer Eingabe geschieht, unterscheidet sich
477zwischen den betrachteten Systemen grundlegend.
478
479Bei einer Command Line kann eine Eingabe eine festge-
480legte Programmfunktion auslösen. Die Utility `mkdir`
481erzeugt beispielsweise die durch ihre Operanden be-
482zeichneten Verzeichnisse. Die Verarbeitung besteht
483hier wesentlich in der Ausführung einer definierten
484Operation (vgl. IEEE/The Open Group 2024, *mkdir*).
485[cite: turn944464search0]
486
487Bei Formularen steht dagegen die Prüfung einer Eingabe
488im Vordergrund. HTML stellt verschiedene Bedingun-
489gen bereit, anhand derer ein Feld als gültig oder un-
490gültig behandelt werden kann. Bei der Übermittlung
491kann geprüft werden, ob die dafür vorgesehenen Felder
492ihre jeweiligen Anforderungen erfüllen (vgl. WHATWG
4932026, Abschn. 4.10.21). [cite: turn269126view1]
494
495Eine Suchmaschine ermittelt aus einer größeren Infor-
496mationsgrundlage mögliche Treffer und bringt sie
497in eine Rangordnung. Bereits das von Brin und Page be-
498schriebene Google-System verband dazu textuelle
499Merkmale mit Informationen aus der Linkstruktur des
500Webs. Die Verarbeitung einer Anfrage besteht somit
501nicht nur darin, passende Dokumente zu finden, son-
502dern auch darin, zwischen ihnen eine Reihenfolge
503herzustellen (vgl. Brin/Page 1998, S. 109–113). [cite:
504turn269126search0]
505
506Bei einem Sprachmodell entsteht die Ausgabe wiederum
507schrittweise. Ausgehend vom bisherigen Text wird
508eine Wahrscheinlichkeitsverteilung über mögliche fol-
509gende Tokens bestimmt; das ausgewählte Token wird Teil
510des weiteren Kontexts, auf dessen Grundlage das nächs-
511te erzeugt wird. Eine Antwort entsteht dadurch als
512fortlaufende Folge einzelner Vorhersagen (vgl. Radford
513et al. 2019, PDF-S. 2, 4 und 6).
514
515Diese Beschreibung erklärt, **wie** Eingaben verarbei-
516tet werden. Sie erklärt jedoch noch nicht, nach wel-
517chen Maßstäben Eingaben akzeptiert, Informationen aus-
518gewählt oder Antworten als erwünscht behandelt werden.
519
520### Festgelegte Handlungsmöglichkeiten und Anforderun-
521gen
522
523Bei Command Line und Formular erscheinen die jeweili-
524gen Maßstäbe zunächst vergleichsweise eindeutig.
525Ein Befehl besitzt eine definierte Funktion, ein For-
526mularfeld kann festgelegten Anforderungen entspre-
527chen oder von ihnen abweichen. Diese Regeln sind jedoch
528nicht einfach Eigenschaften der eingegebenen Zei-
529chenfolge.
530
531Bei `mkdir` legt ein Standard eine bestimmte Funktion
532und die Bedeutung ihrer Operanden fest (vgl. IEEE/The
533Open Group 2024, *mkdir*). Dass gerade diese Funktion
534bereitgestellt wird und in dieser Form aufgerufen
535werden kann, ist damit bereits Teil einer technischen
536Festlegung. Welche weiteren Funktionen eine konkrete
537Umgebung zur Verfügung stellt und unter welchen Bedin-
538gungen sie eingesetzt werden können, hängt wiederum
539von ihrer jeweiligen Implementierung und Konfiguration
540ab. Standard, Software und konkrete Umgebung sind
541dabei nicht dieselbe Entscheidungsebene.
542
543Ähnliches gilt für Formulare. HTML stellt Mechanismen
544bereit, mit denen Eingaben etwa hinsichtlich Typ,
545Vorhandensein oder anderer Bedingungen geprüft werden
546können. Welche Felder ein konkretes Formular ent-
547hält und welche dieser Anforderungen tatsächlich ein-
548gesetzt werden, entscheidet jedoch die jeweili-
549ge Anwendung (vgl. WHATWG 2026, Abschn. 4.10.21). Die
550technische Möglichkeit einer Prüfung ist damit von
551der Entscheidung zu unterscheiden, **was überhaupt ge-
552prüft werden soll**. [cite: turn269126view1]
553
554Für NutzerInnen erscheinen diese Entscheidungen an-
555schließend als Bedingungen ihres Handelns. Sie können
556ihre Eingabe innerhalb der vorgesehenen Möglichkeiten
557verändern, verfügen aber nicht zwangsläufig über die
558Regeln, nach denen eine Funktion bereitgestellt oder
559ein Wert akzeptiert wird. Damit stellt sich nicht
560nur die Frage, ob eine Eingabe technisch gültig ist,
561sondern auch, **wer festlegt, welche Handlungsmög-
562lichkeiten und Anforderungen gelten**.
563
564### Relevanz als gestalteter Maßstab
565
566Bei einer Suche ist der Maßstab weniger eindeutig. Zwi-
567schen einer Anfrage und möglichen Treffern besteht
568keine einfache Entsprechung, aus der sich eine einzige
569richtige Reihenfolge ableiten ließe. Suchsysteme
570müssen deshalb Merkmale auswählen, anhand derer sie die
571Relevanz und Qualität von Inhalten annähern.
572
573Bereits Brin und Page kombinierten dafür unterschiedli-
574che Hinweise wie den Text einer Seite, Verlinkungen
575und die daraus berechnete Bedeutung einer Seite (vgl.
576Brin/Page 1998, S. 109–113). Welche Merkmale be-
577rücksichtigt und wie sie gewichtet werden, beeinflusst
578damit, welche Inhalte für eine Anfrage sichtbar
579werden und in welcher Reihenfolge sie erscheinen.
580
581Relevanz ist in diesem Sinne nicht lediglich etwas, das
582ein Suchsystem in vorhandenen Informationen ent-
583deckt. Sie wird durch Auswahl- und Bewertungsverfahren
584technisch operationalisiert. Gillespie beschreibt
585algorithmische Relevanz entsprechend als Ergebnis von
586Kriterien und Verfahren, deren Gestaltung darüber
587entscheidet, was hervorgehoben und was zurückgestellt
588wird (vgl. Gillespie 2014, S. 175–179, 183–187).
589
590Auch heutige Suchsysteme werden anhand solcher Vorstel-
591lungen von Qualität und Nützlichkeit weiterentwickelt.

593durch externe Search Quality Raters, Side-by-Side-Ver-
