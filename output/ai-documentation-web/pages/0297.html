1489[Text block] ## Iteration und Reformulierung
1490
1491Texteingabe endet nicht zwangsläufig mit dem Absenden.
1492Auf eine Reaktion des Systems kann eine weitere
1493Eingabe folgen. NutzerInnen bewerten das Ergebnis, ver-
1494ändern ihre ursprüngliche Eingabe oder formulieren
1495sie neu. Iteration bezeichnet hier eine solche weitere
1496Eingaberunde nach einer Systemreaktion. Eine Refor-
1497mulierung kann dabei einzelne Wörter verändern, zusätz-
1498liche Informationen ergänzen oder das Anliegen neu
1499ausrichten. Sie ist nicht zwangsläufig eine Fehlerkor-
1500rektur, sondern kann auch daraus entstehen, dass
1501sich das eigene Anliegen während der Nutzung verändert
1502oder genauer wird (vgl. Hearst 2009, S. 3, 7–8).
1503
1504Damit eine weitere Eingabe möglich ist, muss die vorhe-
1505rige Systemreaktion zunächst interpretiert werden.
1506Dabei ist nicht jede Rückmeldung gleich eindeutig. Eine
1507konkrete Fehlermeldung in einem Formular kann bei-
1508spielsweise darauf hinweisen, welches Format erwartet
1509wird. Fehlen solche Hinweise, kann es schwieriger
1510sein, die notwendige Änderung zu erkennen (vgl. Seckler
1511et al. 2014, S. 1279–1282). Bei einem unbefriedi-
1512genden Suchergebnis oder einer unpassenden Modellant-
1513wort ist häufig noch weniger eindeutig, worin das
1514Problem liegt. NutzerInnen können erkennen, dass das
1515Ergebnis nicht ihren Erwartungen entspricht, ohne
1516deshalb bereits zu wissen, wie die Eingabe verändert
1517werden muss (vgl. Zamfirescu-Pereira et al. 2023,
1518S. 9–12).
1519
1520Bei Suchanfragen können Ergebnisse zugleich neue Mög-
1521lichkeiten für die nächste Eingabe eröffnen. Sie
1522zeigen nicht nur, ob eine Anfrage zum Informationsbe-
1523darf passt, sondern können auch neue Begriffe oder
1524Teilaspekte sichtbar machen. Eine Suchanfrage wird des-
1525halb nicht immer nur verbessert, um dasselbe Anliegen
1526genauer auszudrücken. Auch das Verständnis dessen, wo-
1527nach gesucht wird, kann sich im Verlauf verändern.
1528Die Ausgabe des Systems wird damit selbst zur Grundla-
1529ge einer weiteren Eingabe (vgl. Hearst 2009, S. 3,
15307–8).
1531
1532Auch beim Prompting können Modellantworten dazu führen,
1533dass eine Eingabe ergänzt, umgestellt oder genau-
1534er formuliert wird. Eine solche Wiederholung bedeutet
1535jedoch nicht automatisch, dass sich das Ergebnis
1536zuverlässig verbessert. Zamfirescu-Pereira et al. be-
1537obachteten in ihrer BotDesigner-Studie, dass Teil-
1538nehmende ihre Prompts häufig anhand einzelner Antworten
1539veränderten. Eine verbesserte Antwort wurde dabei
1540teilweise bereits als Hinweis darauf verstanden, dass
1541die Änderung funktioniert hatte, obwohl ihre Wir-
1542kung nicht systematisch über weitere Fälle geprüft wur-
1543de (vgl. Zamfirescu-Pereira et al. 2023, S. 9–12).
1544Iteration kann also zu einer gewünschten Veränderung
1545führen, ohne dass daraus bereits eine verlässliche
1546Regel für das Verhalten des Systems folgt.
1547
1548Dabei stellt sich auch die Frage, was überhaupt als
1549Verbesserung gilt. Eine Eingabe kann formal akzeptiert
1550werden, ein Ergebnis kann überzeugend wirken oder das
1551ursprüngliche Anliegen tatsächlich erfüllen. Diese
1552Kriterien müssen nicht zusammenfallen. Subramonyam et
1553al. weisen zudem darauf hin, dass wiederholtes Lesen
1554und Reformulieren dazu führen kann, dass sich die wei-
1555tere Arbeit zunehmend an bereits erzeugten Ausgaben
1556orientiert (vgl. Subramonyam et al. 2024, S. 2, 6–7).
1557Das muss nicht grundsätzlich problematisch sein.
1558Eine veränderte Zielvorstellung kann ebenso Teil eines
1559produktiven Erkenntnisprozesses sein. Entscheidend
1560ist jedoch, ob eine Eingabe im Hinblick auf das eigene
1561Anliegen verändert wird oder ob sich das Anliegen
1562zunehmend an das angebotene Ergebnis anpasst.
1563
1564Systemreaktionen sind damit nicht nur Ergebnisse einer
1565vergangenen Eingabe, sondern können zugleich die
1566nächste Eingabe mitbestimmen. NutzerInnen handeln da-
1567bei auf Grundlage dessen, was sie sehen, wie sie es
1568bewerten und welche Annahmen sie über das System ent-
1569wickeln. Dass ein Ergebnis sichtbar ist, bedeutet
1570jedoch noch nicht, dass nachvollziehbar ist, wie es
1571entstanden ist. Während hier die Interpretation
1572und Anpassung der Eingabe im Mittelpunkt steht, rich-
1573tet sich der Blick im folgenden Abschnitt auf die
1574Verarbeitungsschritte, durch die solche Rückmeldungen
1575überhaupt entstehen. [End text block] Ich finde,
1576dieser Abschnitt sollte eher ruhig bleiben. Er braucht
1577keine sehr starke theoretische Zuspitzung, weil die
1578interessante Bewegung schon klar genug ist: **Systemre-
1579aktion → Bewertung → neue Eingabe → möglicherweise
1580verändertes Anliegen**. Besonders den Prompting-Teil
1581würde ich nicht ausführlicher machen, weil er sonst
