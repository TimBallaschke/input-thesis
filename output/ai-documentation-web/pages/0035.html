3019## Die drei Ebenen von „Input“
3020
3021Ich würde das Konzept zunächst in drei Bedeutungen auf-
3022teilen:
3023
3024### 1. Input als Interface
3025
3026Das sichtbare Textfeld:
3027
3028- klein, - leer, - neutral erscheinend, - offen für na-
3029türliche Sprache, - ohne klare Anzeige dessen, was
3030ein Befehl bewirken kann.
3031
3032Das ist der Gegenstand deiner Arbeit.
3033
3034### 2. Input als Arbeit und Anweisung
3035
3036Deine Prompts sind nicht nur Text, sondern delegieren
3037Tätigkeiten:
3038
3039- recherchieren, - lesen, - vergleichen, - klassifizie-

3042
3043Das Textfeld wird dadurch zu einer Schnittstelle für

3045nicht nur, was du eingibst, sondern welche Rolle du

3047Kurator oder Supervisor?

3049### 3. Input als technische Größe

3053

3055gaben, - Systemanweisungen, - maschinenlesbare Me-
3056tadaten.
3057
3058Hier entsteht die produktive Differenz:
3059
3060```text sichtbarer menschlicher Input ≠ tatsächlich
3061verarbeiteter maschineller Input ```
3062
3063Die Dicke des Buches könnte genau diese Differenz ma-

3066## Was das dicke Buch aussagen könnte
3067
3068Momentan lautet die Aussage ungefähr: viel KI-Prozess,
3069wenig eigentlicher Inhalt. Das ist interessant,
3070aber noch etwas pauschal. Präziser könnte das Buch ein
3071Missverhältnis zeigen zwischen:
3072
3073- einer kurzen Eingabe und ihrem großen technischen

3088

3100## Der kleine lesbare Text zwischen den Dokumentations-
3101seiten
3102
3103Auch diese Trennung kann mehr bedeuten als „wichtiger
3104Text groß, Protokoll klein“. Sie könnte zwei unter-
3105schiedliche Lesbarkeiten zeigen:
3106
3107- Der Thesistext ist für Menschen argumentativ lesbar.
3108- Die Dokumentation ist zwar offengelegt, durch

3110verarbeitet die umfangreiche Dokumentation dagegen

3112matisch Verständlichkeit.
3113
3114Das ist ein spannender Widerspruch: Alles kann offen-

3116ge Schrift könnte also nicht nur Platz sparen, sondern
3117die Grenze zwischen formaler Transparenz und tat-
3118sächlicher Zugänglichkeit thematisieren.
3119
3120Dabei wäre wichtig, dass sie nicht bloß dekorativ un-
3121lesbar wird. Die vollständige Dokumentation sollte
3122weiterhin digital durchsuchbar und grundsätzlich lesbar

3127## Tokenmarker
3128
3129Tokenmarker können funktionieren, wenn klar ist, was
3130sie messen. Ein Marker könnte einen Textabschnitt
3131beispielsweise so begleiten:
3132
3133```text TXT-004 Human prompt: 41 words Process span:
313400:18:34 Input tokens: 3,102,418 Cached input:
31352,941,952 Output tokens: 14,206 Tool operations: 27
3136Sources consulted: 6 Sources cited: 3 ```
3137
3138Das würde das Missverhältnis unmittelbar zeigen. Ich
3139würde aber nicht versuchen, jedes sichtbare Wort
3140mit seinem exakten Modelltoken zu markieren. Tokeni-
3141sierung ist modellabhängig, technisch wechselhaft
3142und für Menschen schlecht lesbar.
3143
3144Interessanter wären drei parallele Zählweisen:
3145
3146- menschliche Wörter im Prompt, - abgerechnete maschi-
3147nelle Input-Token, - Wörter im resultierenden The-
3148sisabschnitt.
3149
3150Damit entsteht pro Passage ein Verhältnis:
3151
3152```text 41 sichtbare Promptwörter → 3.102.418 verarbei-
3153tete Input-Token → 286 Wörter Thesistext ```
3154
3155Diese Relation ist konzeptuell aussagekräftiger als
3156eine bloße Tokenzeilennummer.
